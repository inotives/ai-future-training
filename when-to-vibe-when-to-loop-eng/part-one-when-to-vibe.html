CLAUDE CODE WORKSHOP · PART ONE

Vibe coding gets you to a mock you can react to.

Start from a safe copy, let Claude shape the first screen, then guide the next edit.

This deck guides the first, exploratory part of the workshop. Learners create a local air-quality dashboard mock from the supplied boilerplate and refine it with Claude Code.
THE VIBE PHASE

Use Vibe when quick feedback keeps wrong turns cheap.

Keep the first task visual and small.

Let Claude make a first pass from a clear prompt.

Look at the running page before planning more.

The lesson frames Vibe coding for fast exploration when the visible result is useful and feedback is quick. Use this mock to discover what learners want the dashboard to show.
1 · PREPARE

Copy the starter so experiments stay reversible.

cd when-to-vibe-when-to-loop-eng
cp -R boilerplate my-result
cd my-result
npm install
npm run dev
Open http://localhost:3555

Work in my-result/. Keep boilerplate/ as the starter and result/ as the reference.
Run these commands from the repository root. Keep the development server running. The boilerplate README lists Node.js 20.19+ or 22.12+ as the requirement.
2 · START CLAUDE CODE

The first prompt gives Claude a target and boundaries.

In Claude Code

If Claude Code cannot read the parent folder, open dashboard-agent-prompt.md and paste its full contents into the session. The prompt directs Claude to replace the temperature demo with a synthetic PSI and PM2.5 mock, while leaving the boilerplate and reference result untouched.
3 · INSPECT THE FIRST PASS

Judge the mock by what you can learn from it.

Read

Can you scan PSI and PM2.5 separately?

Explore

Can you select a region on the map or list?

Notice

Are stale, missing, loading, and error states clear?

Keep the fixture synthetic. This screen is a prototype, not a live haze report.

Run the page at localhost:3555. Use the prompt's dashboard requirements to review the hierarchy and interactions. Do not spend this phase building data ingestion or persistence.
4 · REFINE · DATA VIEWS

Change one visible behavior at a time.

Ask for one hourly point per hour. Keep missing readings visible as gaps.

Ask for separate PSI and PM2.5 hourly profiles, with sample counts out of seven.

Ask for hover details. Preserve the click popup for touch screens.

These are the first three refinements in dashboard-change-steps.md. Ask for one change, let Claude implement it, then inspect the running result before continuing.
4 · REFINE · VISUAL CUES

Use color and emphasis to make regional differences legible.

Use the severity bands recorded in the change steps, with a labeled legend.

Strengthen the regional list without reducing reading contrast.

Theme the detail panel to match the selected region's PSI band.

Change steps 4 through 6 define these refinements. Keep labels alongside colors. The sample values and backdrop remain synthetic; do not describe them as live conditions.
THE PROMPTING LOOP

Ask, inspect, then decide the next small change.

“Extend recent trends to 24 hours. Keep missing readings visible as gaps.”One request from the change steps

Ask

Choose one refinement.

Inspect

Run the UI and check it.

Respond

Keep, correct, or narrow it.

Repeat

Move to the next item.

Keep dashboard-change-steps.md open. Use one numbered change at a time rather than pasting all six changes together. This makes cause and effect easier to see and gives the learner room to steer.
