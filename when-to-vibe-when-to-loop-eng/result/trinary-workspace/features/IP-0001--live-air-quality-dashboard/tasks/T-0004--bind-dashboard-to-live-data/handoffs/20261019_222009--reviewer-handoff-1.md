## Findings

- On a region selection, `src/main.ts:104` changes `selected` and requests a new region snapshot. If the request fails, `refresh()` leaves `data` intact (`src/main.ts:130-134`) but renders the new `selected` against the old response's region-specific `series24h` and `hourlyAverages7d` (`src/main.ts:41`, `src/main.ts:57-60`). The trend and seven-day profile can therefore be labelled as the newly selected region while showing the previously selected region's aggregates. On a failed selection refresh, either restore the last response's `selectedRegion` or clearly suppress/mark those region-specific panels until matching data arrives; keep the selection and displayed series consistent.
- `statePanel()` checks for an empty database before checking upstream poll errors (`src/main.ts:66-70`). When both feeds have failed and no observations exist, it displays “No readings stored yet” instead of the known ingestion failure. Check API/provider errors before the no-data branch and show a clear error that also explains no stored readings are available.
- `render()` removes the current Leaflet map at its start (`src/main.ts:77`) and creates a centered zoom-10 map later (`src/main.ts:106-108`). The one-minute refresh calls `render()` (`src/main.ts:134`, `src/main.ts:139`), so any user pan or zoom is reset every minute. Preserve the map instance/view while updating its markers, or retain and restore its center/zoom on data refresh.
