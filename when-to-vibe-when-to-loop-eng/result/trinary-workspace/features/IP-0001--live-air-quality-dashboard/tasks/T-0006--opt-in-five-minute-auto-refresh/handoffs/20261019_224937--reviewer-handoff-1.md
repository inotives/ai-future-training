## Findings

- `server/api.js:6-28` accepts `POST /api/poll-current` without validating the request origin or host. The browser client uses a same-origin Vite proxy, but any cross-origin simple POST that reaches loopback can still execute the handler; CORS only restricts reading the response. This is a background side effect that makes upstream calls and writes observations even when the user's switch is off. Reject requests with a hostile/mismatched browser `Origin` (while preserving legitimate local UI and intentional no-Origin CLI calls), and add a handler test proving cross-origin requests do not invoke ingestion.
- `src/main.ts:148-149` takes the no-change branch into `render()`. `render()` replaces `app.innerHTML`, removes/recreates the Leaflet map, and rebuilds all dashboard panels. That contradicts the scoped behavior/documentation to update only the last-check result without refreshing the panels. Update the status element in place on a clean no-change check (or otherwise preserve existing panel DOM/map/focus) and test that no-change leaves panels/interaction state intact as it updates the check time.
- `server/index.js:12-15` starts listening, then launches `ingestion.start()` asynchronously; the initial browser `refresh()` can race the startup provider poll. On a clean DB it can render the empty state before ingestion completes. Since the server no longer polls periodically and the auto-refresh preference is off by default, the page receives no later snapshot unless the user enables auto refresh or reloads. Add a one-time safe reconciliation for startup-in-progress (for example, have initial snapshot/request wait for or observe the startup check, or schedule a one-shot UI snapshot refresh after the startup check completes) and cover the race with a gated fake provider test. Keep recurring server polls disabled.

## API, lifecycle, and limiter review

- `POST /api/poll-current` is exact-path and method gated, and returns HTTP 200 with `changed`, `recordsWritten`, `checkedAt`, error, and feed error details when provider polling partially/fully fails. This lets the UI consume partial updates while transport errors remain non-2xx. It has no request-body parsing or CORS grant. Because the action changes local data/uses provider quota, origin semantics should be explicit; loopback binding alone does not stop browser-originated simple requests.
- `pollCurrent()` returns a shared active promise, waits for both PSI and PM2.5, and on partial failure attaches change/record/feed-error info to the aggregate error. Handler preserves this information. `upsertObservation()` updates `fetched_at` on duplicate identical samples while keeping `changed` false; source timestamp/value changes report true.
- Frontend shares `checkInFlight`, calls `refresh()` on changed/error and preserves stored snapshot during provider error. Success/no-change updates last check; current implementation rebuilds the DOM via `render()` rather than limiting the update to the status element.
- `server/index.js` shutdown still calls and awaits `ingestion.stop()` before DB close. POST in-flight work is not aborted but remains single-flight/limiter-governed and is awaited by service stop; no DB-close race was found. `scripts/dev.mjs` routes the same local API through the Vite proxy.
